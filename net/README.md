## portscan

This benchmark performs a two-stage network port scan against a target list, combining shell-driven control flow with `nmap` for connectivity discovery, exhaustive TCP scanning, and per-host version detection.

### Inputs

- `inputs/localhost.txt`: Target list (default: `127.0.0.1`). The harness spins up persistent `netcat` listeners on ports 4444/5555/6666 so the scan has open services to detect.

### Running

`portscan.sh` validates the supplied IPs, runs `nmap -sn` to identify live hosts, performs a full TCP scan, parses the greppable output with `awk` to collect open ports per host/protocol, and then launches a bounded fan-out of `-sV` version-detection scans in parallel.

The final report is written to `outputs/portscan.txt`.

### Validation

Correctness is determined by computing the SHA-256 hash of each output file and comparing it against a reference hash stored in `hashes/`.

## ping

This benchmark performs an IP sweep across a `/24` subnet and an explicit IP list, capturing reachability for each host.

### Inputs

- `inputs/ping_<size>.txt`: A list of target IPs generated by
  `utils/create_ips.py`.

### Running

`ping.sh` iterates over `1..254` for the given subnet prefix and pings each address, then walks an explicit target file and records each host as `UP` or `DOWN`.

Outputs are stored as `outputs/ping_<size>.txt`.

### Validation

Correctness is determined by computing the SHA-256 hash of each output file and comparing it against a reference hash stored in `hashes/`.

## accept-ips

This benchmark configures an SSH allowlist with `iptables`, exercising firewall-rule generation from a list of trusted IPs.

### Inputs

- `inputs/ips_<size>.txt`: A list of IPs to allow SSH access from, generated by `utils/create_ips.py`.

### Running

`accept-ips.sh` installs baseline `ACCEPT` rules for the loopback interface and for established connections, appends one `ACCEPT` rule per IP in the input list, and finishes with a default `DROP` for the SSH port. The final rule set is captured with `iptables -L INPUT -n`.

The benchmark runs inside a dedicated Linux network namespace
(`koala_bench_<pid>`) created by `execute.sh` with a veth pair and NAT, so the rules do not affect the host. The report is written to
`outputs/accept-ips_<size>.txt`.

### Validation

Correctness is determined by computing the SHA-256 hash of each output file and comparing it against a reference hash stored in `hashes/`.
